\subsubsection{Filtro comb}
Dado que se desea analizar los armónicos de la red, debemos de diseñar un filtro que disponga de ganancia unitaria para estos y las componentes restantes. En función de ello se solicita la característica de atenuar al menos 10 veces las frecuencias múltiplo impar de 25Hz. 

En vista de diseñar tal filtro, se dispone de la siguiente ecuación en diferencias:

\begin{equation}
y_1[n] = \alpha x[n] + \beta y_1[n-k]
\end{equation}

\noindent donde hemos de determinar $\alpha$, $\beta$ y $k$. Para ello podemos realizar un análisis desde la función transferencia del sistema:

\begin{equation}
    H_{(z)} = \frac{{Y_1}_{(z)}}{{X}_{(z)}} = \frac{\alpha}{1-\beta z^{-k}} = \frac{\alpha \cdot z^k}{z^k-\beta}
\end{equation}

\noindent donde resulta evidente que se dispone de k ceros en el origen y k polos repartidos uniformemente en una circunferencia de radio $\beta^{1/k}$. De este modo, k ha de corresponder con la cantidad de armónicos de 50Hz que entran en $f_s = 10kHz$; de este modo, k=200. Luego debemos de ajustar $\alpha$ y $\beta$ tal de obtener las ganancias deseadas. En función de ello se puede analizar la respuesta en frecuencia del sistema:

\begin{align*}
    |H_{(\omega)}| = \frac{\alpha}{\sqrt{(cos(\omega k) - \beta)^2 + sen^2(\omega k)}} = \frac{\alpha}{\sqrt{1 + \beta^2  - 2 \cdot \beta \cdot cos(\omega k)}} = 
\end{align*}

\noindent de este modo, la ganancia en los picos esta dada cuando $\omega = 2\pi / k$, tal que:

\begin{equation}
    \frac{\alpha}{1-\beta} = 1 \Longrightarrow \alpha = 1-\beta
\end{equation}

\noindent mientras que los múltiplos impares de 25Hz corresponden a $\omega = \frac{2\pi \cdot m \cdot 25Hz}{2\pi \cdot f_s} = m \cdot \frac{\pi}{k}$ con m impar. Por ende:

\begin{equation}
    \frac{\alpha}{1+\beta} = 0.1 \Longrightarrow \alpha = 0.1 + 0.1\beta
\end{equation}

\noindent resolviendo el sistema de ecuaciones se obtiene $\alpha = 2/11$ y $\beta = 9/11$.

\subsubsection{Pasa-bajos | Recuperación de primeros 10 armónicos}
En segundo lugar se debe diseñar un filtro pasa-bajos tal que se recuperen los primeros 10 armónicos, donde la atenuación subsecuente ha de ser de al menos 20dB. Para lograr este acometido se ha de diseñar un filtro FIR mediante el método de la serie de Fourier (análogo al ejercicio 1). En función de ello se ha de decidir la ventana óptima para la tarea.

En este caso particular la decisión es más compleja que las circunstancias planteadas para el ejercicio 1. Por un lado se ha de considerar que la ganancia en la banda de atenuación no es tan restrictiva como lo fue en el primer caso. Una atenuación de 20dB es lo suficientemente pequeña tal que se pueda emplear una ventana rectangular, por lo que potencialmente se puede aprovechar la gran caída de la misma para optimizar el número de taps que ha de disponer el filtro. Sin embargo, esta ventana dispone de un problema fundamental: el fenómeno de Gibbs. La respuesta en frecuencia presenta oscilaciones en la banda pasante. Estas oscilaciones potencialmente pueden llegar a ser críticas para el cálculo del THD, dado que en el esquema de la Figura \ref{fig: esquema gral a implementar} no se dispone de un método para discernir de los armónicos y compensar esta atenuación. En función de ello se puede decidir optar por otra ventana que no disponga de esta problemática, como puede ser una ventana de Hamming. Esta ventana no dispone de estas oscilaciones pronunciadas, sin embargo el número de taps a emplear potencialmente crece drásticamente respecto de la primera opción. En función de ello se sugiere el uso de una tercera opción que no fue analizada en el primer ejercicio: la ventana de Kaiser. Esta ventana dispone de un parámetro adicional ($\beta$), que le confiere un grado de libertad que permite ajustar la ciada y atenuación del lóbulo lateral. De este modo podemos intentar encontrar un punto intermedio entre los beneficios que confieren las ventanas previamente mencionadas, optimizando para nuestro beneficio.

En función de ello se realizó un código en Python tal que se trimmeo el número de taps y $\beta$ (en el caso de la ventana de Kaiser), con tal de cumplir las especificaciones requeridas. Para la frecuencia de cruce que requiere como parámetro de entrada la función \emph{signal.firwin()} se empleó fc=525Hz (notar que si se usa 500Hz potencialmente se estaría incurriendo en un error al atenuar un armónico relevante para el cálculo del THD). \subsubsection{Simulación}
En última instancia se pide implementar el esquema completo y simularlo con la siguiente señal:

\begin{equation}
x[n] = A_1 \cdot sin(2\pi \cdot n \cdot f_0/f_s) + \sum_{k=2}^K A_k \cdot sin(2\pi kf_0 \cdot nf_s)
\end{equation}

\noindent donde $f_0=50Hz$, $f_s=10kHz$ y $A_k$ es el k-esimo número de la sucesión de Fibonacci.

El THD de esta señal se puede calcular como:

\begin{equation}
    THD = \frac{\sum_{k=2}^K 1/2 \cdot A_k^2}{1/2 \cdot A_1^2}
\end{equation}

\noindent por lo que podemos emplear esta misma para validar el sistema diseñado hasta aquí. Para ello se realizó una simulación, donde se generó un segundo de esta señal y se la inyectó al sistema. Una vez que se acabó el transitorio se midieron los valores RMS de la señal de salida y se calculó el THD como:

\begin{equation}
    THD_{medido} = \frac{\sqrt{V_t^2 -V_0^2}}{V_0}
\end{equation}

import numpy as np
import matplotlib.pyplot as plt
from scipy import signal

# --- 1. Parametros Globales ---
fs = 10000
duration = 1.0  # 1 segundo
t = np.arange(0, duration, 1/fs)
f0 = 50

# --- 2. Generacion de Senal Sintetica (Fibonacci) ---
def fibonacci_amplitudes(n_harmonics):
    fib = [1, 1]
    for i in range(2, n_harmonics + 2):
        fib.append(fib[-1] + fib[-2])
    # Ak = 1 / f_{k+1}
    return [1/fib[k] for k in range(1, n_harmonics + 1)]

# Generamos armonicos hasta Nyquist (fs/2 = 5000Hz -> 100 armonicos)
K = 100 
A = fibonacci_amplitudes(K)
x = np.zeros_like(t)

for k in range(1, K + 1):
    x += A[k-1] * np.sin(2 * np.pi * k * f0 * t)

# --- 3. Filtro Comb (y1) ---
# y1[n] = alpha*x[n] + beta*y1[n-k]
alpha = 2/11
beta = 9/11
k_delay = 200

# Implementacion recursiva del Comb
# b = [alpha], a = [1, 0, 0, ..., -beta]
b_comb = [alpha]
a_comb = np.zeros(k_delay + 1)
a_comb[0] = 1
a_comb[k_delay] = -beta
y1 = signal.lfilter(b_comb, a_comb, x)

# --- 4. Filtros FIR Kaiser (y2 e y3) ---
# y2: Recupera 10 armonicos
n2 = 281
beta2 = 1.8
fc2 = 530
taps_y2 = signal.firwin(n2, fc2, fs=fs, window=('kaiser', beta2))
y2 = signal.lfilter(taps_y2, [1.0], y1)

# y3: Recupera fundamental
n3 = 281
beta3 = 2.0
fc3 = 75
taps_y3 = signal.firwin(n3, fc3, fs=fs, window=('kaiser', beta3))
y3 = signal.lfilter(taps_y3, [1.0], y1)

# --- 5. Calculo de THD ---
# Para evitar el transitorio inicial de los filtros, descartamos el primer tramo
offset = 5000 
y2_steady = y2[offset:]
y3_steady = y3[offset:]

# Valores RMS
Vt = np.sqrt(np.mean(y2_steady**2))
V0 = np.sqrt(np.mean(y3_steady**2))

# THD = sqrt(Vt^2 - V0^2) / V0
thd_calculado = (np.sqrt(Vt**2 - V0**2) / V0) * 100

# --- 6. Validacion Teorica ---
# THD_teorico usando los primeros 10 armonicos (A1 a A10)
sum_sq_harmonics = np.sum(np.array(A[1:10])**2)
thd_teorico = (np.sqrt(sum_sq_harmonics) / A[0]) * 100

print(A)
print(f"--- Resultados del Analizador ---")
print(f"V_total (10 armonicos): {Vt:.4f}")
print(f"V_fundamental (V0):     {V0:.4f}")
print(f"THD calculado:          {thd_calculado:.2f}%")
print(f"THD teorico (H2-H10):   {thd_teorico:.2f}%")

# --- 7. Visualizacion ---
plt.figure(figsize=(12, 5))
plt.plot(t[offset:offset+1000], y2[offset:offset+1000], label='y2 (10 Armonicos)')
plt.plot(t[offset:offset+1000], y3[offset:offset+1000], label='y3 (Fundamental)', linewidth=2)
plt.legend()
plt.grid(True)
plt.show()
\end{lstlisting}

\subsection{Análisis de implementación}
Si bien el sistema diseñado cumple con las especificaciones requeridas, existen ciertos riesgos a la hora de realizar la implementación.
\subsubsection{Implementación en punto fijo}
El cálculo del valor RMS de una señal involucra la operación:

\begin{equation}
V_{RMS} = \sqrt{\frac{1}{N} \sum_{n=0}^{N-1} y[n]^2}
\end{equation}

\noindent La presencia de la raíz cuadrada y la división por N provocan que inherentemente la sumatoria de los cuadrados se desvié ampliamente del rango de la señal original y el valor RMS a calcular. Por ende, este da origen a un riesgo de overflow al implementarlo en punto fijo si no se toman las precauciones necesarias. 

Una forma de mitigar este riesgo es realizar un cálculo del promedio móvil de los cuadrados, es decir, en lugar de calcular la sumatoria de los cuadrados de toda la señal, se puede calcular la sumatoria de los cuadrados de un bloque de muestras y luego dividir por el número de muestras en ese bloque. De este modo, se mantiene el valor dentro de un rango manejable y se reduce el riesgo de overflow:

\begin{equation}
MS_{n} = MS_{n-1} + \frac{y[n]^2 - MS_{n-1}}{n}
\end{equation}

\subsubsection{FFT como alternativa}
Se sugiere el uso de la FFT como alternativa para el cálculo del THD, empleando la amplitud de los armónicos asociados para determinar los valores RMS.

Este método dispone de una ventaja de cálculo con respecto a lo observado en la implementación propuesta (notar el orden de los filtros diseñados); donde inclusive se podría emplear el algoritmo de Goertzel (algoritmo óptimo para el cálculo de bines individuales de la DFT) con tal de optimizar aun más el cálculo de los armónicos de interés. No obstante, esta alternativa dispone de un riesgo asociado: ¿Qué ocurre si los armónicos no coinciden exactamente con los bines de la FFT?

En un principio, dado que se conoce de antemano el contenido espectral que se desea medir, es posible tomar una ventana adecuada para minimizar el leakage y así obtener una medición precisa de los armónicos. Sin embargo, a diferencia del filtro comb implementado, esta alternativa no evita que el contenido espectral de la señal de entrada que esta en las inmediaciones de los armónicos de interés se asocie al bin calculado, por lo que este leakage es potencialmente riesgoso (aunque si la señal sensada es lo suficientemente limpia no debería de ser crítica esta cuestión). 

Finalmente, se ha de tener en cuenta que ocurriría si la frecuencia fundamental no corresponde exactamente con 50Hz (dado que el diseño del procedimiento previamente descrito involucra esta cuestión). De ser así los armónicos a estudiar no coincidirán con los bines de la FFT, por lo que la amplitud de los mismos variaría en correspondencia con la diferencia de frecuencia y la ventana empleada. Sin embargo, notar que en el método implementado no estamos exceptuados de esta problemática, en tanto y en cuanto el filtro comb tiene un ancho de banda acotado, por lo que fluctuaciones de la fundamental alteran también la amplitud de la señal obtenida, aunque en principio es menos crítico.

#define FIR_TAP1    281
#define FIR_TAP2    281
#define COMB_DELAY  200

const float taps_FIR1[281] = {...};
const float taps_FIR2[281] = {...};

void FIR_Process_Buffer(float *in, float *out, int numElem, float *state, int *pIdx, const float *taps, int numTaps);
float RMS_calculator(float *s, int numElem);

// Estados para los filtros 
static float state_comb[COMB_DELAY] = {0};
static int idx_comb = 0;

static float state_y2[FIR_TAP1] = {0};
static int idx_y2 = 0;

static float state_y3[FIR_TAP2] = {0};
static int idx_y3 = 0;

// Parametros del Comb
const float alpha = 0.18181f; // 2/11
const float beta  = 0.81818f; // 9/11

void my_app(void)
{
	static float modul = 0.5;
	volatile uint16_t *adc_in = GetBufferIn();
	volatile uint16_t *dac_out = SetBufferOut();

	TurnON(TP0);

	// Senales a implementar
	static float y1[BUFFER_SIZE];
	static float y2[BUFFER_SIZE];
	static float y3[BUFFER_SIZE];

	int i,j;

	for (int i = 0; i < BUFFER_SIZE; i++)
	{
	    float x_n = (float)adc_in[i] - 2048.0f;

	    // Leemos el valor que tiene el delay (la salida se hace D muestras)
	    volatile float delayed_y = state_comb[idx_comb];

	    // Calculamos la salida actual siguiendo y[n] = a*x[n] + b*y[n-D]
	    y1[i] = (alpha * x_n) + (beta * delayed_y);

	    // Guardamos la salida actual en el buffer de estado para que sea
	    //    el "delayed_y" dentro de D muestras
	    state_comb[idx_comb] = y1[i];

	    // Avanzamos el puntero circular
	    idx_comb++;
	    if (idx_comb >= COMB_DELAY) idx_comb = 0;
	}

	FIR_Process_Buffer(y1, y2, BUFFER_SIZE, state_y2, &idx_y2, taps_FIR1, FIR_TAP1);
	FIR_Process_Buffer(y1, y3, BUFFER_SIZE, state_y3, &idx_y3, taps_FIR2, FIR_TAP2);

	float V0 = RMS_calculator(y3, BUFFER_SIZE);
	float Vt = RMS_calculator(y2, BUFFER_SIZE);

	float THD = sqrtf(Vt * Vt - V0 * V0)/V0;

	for (int i = 0; i < BUFFER_SIZE; i++)
		dac_out[i]= (uint16_t)(THD * 4095.0f);

	modul *=alternate;
	TurnOFF(TP0);

}

/**
 * @brief Procesa un buffer completo de entrada y genera uno de salida.
 * @param in       Puntero al buffer de entrada (ej: y1_buffer)
 * @param out      Puntero al buffer donde se guardara la salida (ej: y2_buffer)
 * @param numElem  Tamano del buffer (BUFFER_SIZE, ej: 1024)
 * @param state    Array de historial (debe ser estatico y de tamano numTaps)
 * @param pIdx     Puntero al indice actual del buffer circular (mantiene el estado entre bloques)
 * @param taps     Array de coeficientes
 * @param numTaps  Cantidad de coeficientes (281)
 */
void FIR_Process_Buffer(float *in, float *out, int numElem, float *state, int *pIdx, const float *taps, int numTaps)
{
    // Bucle que recorre cada muestra del buffer de entrada
    for (int i = 0; i < numElem; i++)
    {
        // Guardar la muestra actual en el buffer circular de estado
        state[*pIdx] = in[i];

        // Convolucion: Multiplicar y Acumular (MAC)
        float acc = 0.0f;
        int currIdx = *pIdx;

        for (int j = 0; j < numTaps; j++)
        {
            acc += taps[j] * state[currIdx];

            // Retroceder en el buffer circular
            currIdx--;
            if (currIdx < 0) {
                currIdx = numTaps - 1;
            }
        }

        // Escribir el resultado en el buffer de salida
        out[i] = acc;

        // Avanzar el puntero del buffer circular para la PROXIMA muestra
        *pIdx = (*pIdx + 1) % numTaps;
    }
}


float RMS_calculator(float *s, int numElem)
{
    float acc = 0.0f;
    for (int i = 0; i < numElem; i++)
    {
        float val = s[i];
        acc += val * val;
    }
    
    return sqrtf(acc / (float)numElem);
}

\end{lstlisting}

En vista a debuggear este código se verificó que el tiempo de cálculo de los filtros no supere el tiempo de adquisición de cada bloque. Este ensayo se realizó  mostrando a la salida la entrada, donde se pudo observar la entrada sin distorsión alguna, por lo que se concluye que el tiempo de cálculo es menor al tiempo de adquisición. 

Con tal de verificar que la secuencia empleada no sea errónea, se procedió a generar mediante python una señal de prueba, junto con el set de \emph{golden values} asociados:


\vspace{0.5cm}
\begin{lstlisting}[style=mystyle, caption={Código empleado para generar input \& golden.}, label={lst:filtro + ds}]
import numpy as np
import matplotlib.pyplot as plt
from scipy import signal

# --- Configuracion identica al codigo C ---
BUFFER_SIZE = 1000
SAMPLE_RATE = 10000  # 10 kHz
COMB_DELAY = 200
ALPHA = 0.18181
BETA = 0.81818

def generate_inputs(filename, duration_sec=1.0):
    """Genera una senal de prueba: Seno de 50Hz + 3er armonico + Ruido"""
    t = np.arange(0, duration_sec, 1/SAMPLE_RATE)
    
    # Amplitudes para el calculo del THD esperado
    # Fundamental (50Hz) y 3er Armonico (150Hz)
    amp_fund = 1000.0
    amp_harm = 300.0
    
    fundamental = amp_fund * np.sin(2 * np.pi * 50 * t)
    harmonico = amp_harm * np.sin(2 * np.pi * 150 * t)
    ruido = 50 * np.random.normal(size=len(t))
    
    signal_float = 2048 + fundamental + harmonico + ruido
    signal_uint16 = np.clip(signal_float, 0, 4095).astype(np.uint16)
    
    np.savetxt(filename, signal_uint16, fmt='%d')
    print(f"Archivo de entrada '{filename}' generado.")
    
    # Retornamos la senal y el THD teorico (armonico / fundamental)
    thd_teorico = amp_harm / amp_fund
    return signal_uint16, thd_teorico

def golden_model(input_signal, taps_fir1, taps_fir2):
    """Implementa la logica del codigo C en Python"""
    x = input_signal.astype(float) - 2048.0
    
    # 1. Filtro Comb
    y1 = np.zeros_like(x)
    for n in range(len(x)):
        delayed_val = y1[n - COMB_DELAY] if n >= COMB_DELAY else 0
        y1[n] = ALPHA * x[n] + BETA * delayed_val
        
    # 2. Filtros FIR
    y2 = np.convolve(y1, taps_fir1, mode='same')
    y3 = np.convolve(y1, taps_fir2, mode='same')
    
    # 3. Calculo de THD por bloques
    thd_output = []
    for i in range(0, len(y1), BUFFER_SIZE):
        block_y2 = y2[i:i+BUFFER_SIZE]
        block_y3 = y3[i:i+BUFFER_SIZE]
        
        if len(block_y2) < BUFFER_SIZE: break
        
        v0 = np.sqrt(np.mean(block_y3**2))
        vt = np.sqrt(np.mean(block_y2**2))
        
        # THD = sqrt(Vt^2 - V0^2) / V0
        thd = np.sqrt(np.abs(vt**2 - v0**2)) / v0 if v0 > 1e-6 else 0
        thd_output.extend([int(thd * 4095)] * len(block_y2))
        
    return thd_output

if __name__ == "__main__":
    # 1. Generar entrada y obtener THD teorico
    input_data, thd_esperado = generate_inputs("input_samples.txt")
    
    # 2. Diseno de filtros (usando SAMPLE_RATE definido arriba)
    fs = SAMPLE_RATE
    
    # FIR 1: Pasa-todo o banda ancha para Vt
    n2, beta2, fc2 = 281, 1.8, 530 
    taps_f1 = signal.firwin(n2, fc2, fs=fs, window=('kaiser', beta2))

    # FIR 2: Pasa-bajos para V0 (Fundamental)
    n3, beta3, fc3 = 281, 2.0, 75
    taps_f2 = signal.firwin(n3, fc3, fs=fs, window=('kaiser', beta3))
    
    # 3. Ejecutar modelo
    golden_result = golden_model(input_data, taps_f1, taps_f2)
    
    # 4. Calcular THD final obtenido (promedio de la salida del DAC)
    # Convertimos de escala 0-4095 de vuelta a flotante 0.0-1.0
    thd_final = np.mean(golden_result) / 4095.0
    
    # 5. Impresion de resultados
    print("\n" + "="*45)
    print(f"{'ANALISIS DE RESULTADOS (GOLDEN MODEL)':^45}")
    print("="*45)
    print(f"Frecuencia de Muestreo: {SAMPLE_RATE} Hz")
    print(f"THD Esperado (Teorico):  {thd_esperado:.4f} ({thd_esperado*100:.2f}%)")
    print(f"THD Final (Procesado):   {thd_final:.4f} ({thd_final*100:.2f}%)")
    print(f"Error absoluto:          {abs(thd_esperado - thd_final):.4f}")
    print("="*45)
    
    # 6. Guardar referencia
    np.savetxt("golden_reference.txt", golden_result, fmt='%d')
    print("Golden Reference generado en 'golden_reference.txt'.")

Para generar la salida en C se empleo el siguiente código:


\vspace{0.5cm}
\begin{lstlisting}[style=mystyle, caption={Código empleado para generar salida de C.}, label={lst:filtro + ds}]
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <stdbool.h>
#include <math.h>

#define BUFFER_SIZE 1000
#define FIR_TAP1    281
#define FIR_TAP2    281
#define COMB_DELAY  200

// --- Coeficientes --
const float taps_FIR1[281] = {...};
const float taps_FIR2[281] = {...};

// --- Variables de Estado Globales ---
static float state_comb[COMB_DELAY] = {0};
static int idx_comb = 0;
static float state_y2[FIR_TAP1] = {0};
static int idx_y2 = 0;
static float state_y3[FIR_TAP2] = {0};
static int idx_y3 = 0;

const float alpha = 0.18181f;
const float beta  = 0.81818f;

// --- Prototipos ---
void FIR_Process_Buffer(float *in, float *out, int numElem, float *state, int *pIdx, const float *taps, int numTaps);
float RMS_calculator(float *s, int numElem);

int main(int argc, char *argv[]) {
    if (argc < 3) {
        printf("Uso: %s <archivo_entrada.txt> <archivo_salida.txt>\n", argv[0]);
        return 1;
    }

    FILE *fin = fopen(argv[1], "r");
    FILE *fout = fopen(argv[2], "w");

    if (!fin || !fout) {
        perror("Error al abrir los archivos");
        return 1;
    }

    uint16_t adc_buffer[BUFFER_SIZE];
    float y1[BUFFER_SIZE], y2[BUFFER_SIZE], y3[BUFFER_SIZE];
    
    printf("Procesando...\n");

    // Bucle principal: lee bloques de BUFFER_SIZE hasta el fin del archivo
    while (!feof(fin)) {
        int samples_read = 0;
        
        // 1. Leer datos del archivo (asumiendo valores enteros 0-4095)
        for (int i = 0; i < BUFFER_SIZE && !feof(fin); i++) {
            if (fscanf(fin, "%hu", &adc_buffer[i]) == 1) {
                samples_read++;
            }
        }

        if (samples_read == 0) break;

        // 2. Procesamiento Comb Filter
        for (int i = 0; i < samples_read; i++) {
            float x_n = (float)adc_buffer[i] - 2048.0f;
            float delayed_y = state_comb[idx_comb];
            y1[i] = (alpha * x_n) + (beta * delayed_y);
            state_comb[idx_comb] = y1[i];
            idx_comb = (idx_comb + 1) % COMB_DELAY;
        }

        // Procesamiento FIR
        FIR_Process_Buffer(y1, y2, samples_read, state_y2, &idx_y2, taps_FIR1, FIR_TAP1);
        FIR_Process_Buffer(y1, y3, samples_read, state_y3, &idx_y3, taps_FIR2, FIR_TAP2);

        // Calculo de THD
        float V0 = RMS_calculator(y3, samples_read);
        float Vt = RMS_calculator(y2, samples_read);
        
        // Evitar division por cero
        float THD = (V0 > 0.0001f) ? sqrtf(fabsf(Vt * Vt - V0 * V0)) / V0 : 0.0f;

        // 5. Generar salida (Escribir el valor de THD mapeado a 12 bits)
        for (int i = 0; i < samples_read; i++) {
            uint16_t out_val = (uint16_t)(THD * 4095.0f);
            fprintf(fout, "%u\n", out_val);
        }
    }

    fclose(fin);
    fclose(fout);
    printf("Proceso completado con exito.\n");

    return 0;
}

// --- Implementaciones de funciones ---

void FIR_Process_Buffer(float *in, float *out, int numElem, float *state, int *pIdx, const float *taps, int numTaps) {
    for (int i = 0; i < numElem; i++) {
        state[*pIdx] = in[i];
        float acc = 0.0f;
        int currIdx = *pIdx;
        for (int j = 0; j < numTaps; j++) {
            acc += taps[j] * state[currIdx];
            if (--currIdx < 0) currIdx = numTaps - 1;
        }
        out[i] = acc;
        *pIdx = (*pIdx + 1) % numTaps;
    }
}

float RMS_calculator(float *s, int numElem) {
    float acc = 0.0f;
    for (int i = 0; i < numElem; i++) {
        acc += s[i] * s[i];
    }
    return sqrtf(acc / (float)numElem);
}
